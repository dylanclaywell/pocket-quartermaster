## Storage quartermaster — shipped

Space-aware ROM curation: per-device budgets + prune suggestions joined from playtime, with strictly user-confirmed deletion.

### What landed
- **`GET /api/storage`** (NEW, read-only) — folds rom caches + activity caches + live statfs. Returns per-source `{sizeBytes,freeBytes,romBytes,romCount}` + `pruneCandidates` (one per game×source: filenames, bytes, playSeconds, backedUpElsewhere) + totalCandidates + reclaimableBytes. Candidates sorted worst-first by `bytes/(playSeconds+1)`; capped at 200 with totalCandidates reported (no silent truncation).
- **`POST /api/roms/destination/remove`** (NEW) — the only ROM-delete path. Re-resolves romsRoot via `resolveRomSourceRoots`, trusts the cache for relPaths (not client), containment-guards every path inside the mounted root, refuses unmounted sources, unlinks, then `refreshRomCache`. Returns removed/freedBytes/errors.
- **`pages/storage.vue`** — device used/free bars + footprint; prune list with "never-played only" toggle (default on), only-copy vs backed-up pills; sticky reclaim bar → confirm dialog naming count/bytes and warning on only-copies → loops the delete endpoint per candidate.
- **`app.vue`** — added Storage nav link.

### Name-join
Resolved as direct: ROM `gameKey` IS activity `normalizedName` (both `normalizeGameName(displayName)`), so footprint→playtime is a key match, no new normalizer.

### Safety (per user, non-negotiable)
Never auto-delete. Three gates: read-only suggest → user select+confirm → server path-validate. Documented in the plan's "Core principle" section.
