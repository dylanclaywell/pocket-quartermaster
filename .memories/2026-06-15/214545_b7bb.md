## Activity dashboard + runtime-snapshot trends — shipped

Turned scanned RetroArch playtime into the home control-tower view, plus real daily/weekly trends derived from append-only runtime snapshots.

### What landed
- `server/utils/activityHistory.ts` (NEW) — `appendSnapshot` / `loadHistory` / `listHistoryKeys` over per-source JSONL at `{CONFIG}/activity-history/{cacheKey}.jsonl`.
- `refreshCache` (`server/utils/activityCache.ts`) now appends a `{at,totalSeconds,games}` snapshot after each scan, folded per `normalizedName`. Wrapped in try/catch — never breaks a scan.
- `GET /api/activity/trends?days=N` (NEW) — buckets snapshots by server-local day, diffs successive observed days (delta clamped ≥0, attributed to later day), sums across sources. Returns `{days[], weekSeconds, streakDays, haveHistory}`.
- `components/Sparkline.vue` (NEW) — dependency-free SVG bar sparkline (no chart lib; Pi bundle stays small).
- `pages/index.vue` — added headline tiles (total played / games / sessions), This-week sparkline + streak with "building history" empty state, hours-by-device split, and a Most-played grid (by totalSeconds, distinct from existing Recently-played by lastPlayedAt).

### Why snapshots
`.lrtl` stores cumulative runtime only — no session history. Diffing successive scan snapshots is the only way to get per-day deltas. No backfill: UI shows "building history" until `haveHistory` (≥2 snapshots on any source).

### Verified
- `npm run typecheck` clean.
- Dev server: `/api/activity/trends` 200, home page 200.
- Synthetic 3-snapshot history (1000→4600→7000 across d-3/d-1/today): produced yesterday=3600, today=2400, week=6000, streak=2 — gap-spanning diff lands on the later observed day as designed. Test file removed, dev server killed.
